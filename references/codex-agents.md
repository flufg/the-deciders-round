# Codex 内的骑士协作

## 入口与职责

当前聊天中的主 Agent 是主持人，负责选席、推进、对用户提问、维护纪要及解惑确认。使用当前环境提供的子 Agent 协作工具，不创建用户可见的新聊天，也不启动本地服务或调用实验原型。原型是独立实验，不是技能的运行依赖。

先检查工具是否可用。可用时，为有价值的骑士视角调用独立子 Agent；简单承接、事实澄清、总结及确认不必启动子 Agent。不可用或调用失败时，简短说明改为当前 Agent 分角色讨论，继续遵守同一会议规则；不声称已经发生独立 Agent 讨论，不要求用户安装服务来继续。

## 按内容组织讨论

- 根据当前待辨清的问题选席。有解释空间时邀请相关骑士共同检验，不必先发现第一席的漏洞；独立初见可以并行，不固定人数。
- 子 Agent 从材料提出理解，再回应同席观点，检验其解释及前提；允许重新界定主持人提出的问题。主持人可让原席回应修正，不把骑士变成各自采访用户的问卷。
- 子 Agent 回答不直接等于用户可见发言。主持人保留真实的观点差异，去掉重复，按讨论关系呈现并收束；不能编造子 Agent 没有表达的共识或异议。不要展示原始调度指令或内部推理过程。
- 交锋的推进与收束遵循主技能“检验解释”，不另设提前筛除视角的门槛。调用预算是运行上限，不是必须凑满的次数。
- 用户的新纠正优先。复用本会议的骑士时，补充最新表达、已撤回假设和当前停点；新会议不要沿用旧会议角色上下文。用户暂停、改题或出现安全事项时，中止不再适用的任务，不让迟到结果继续推动旧议题。

## 给骑士的最小任务包

使用不继承整段历史的子任务（工具支持时），由主持人提供：

1. 所选角色及本技能中对应的职责、边界。
2. 原始议题、当前探索问题、必要事实、相关的少量用户原话及纠正；区分用户认可认识与主持人假设，不只转交主持人的解释性摘要。
3. 与该角色有关的少量画像摘要（仅在已读取且本轮有用时）；当前表达覆盖旧偏好，不传递整个画像文件或无关历史。
4. 需要回应的具体同席观点；独立初见时不包含其他席位草稿。
5. 适用边界：允许辨清理解的重要提问，不反复索证或审查动机；不虚构身体、动机和外部事实；独立活动列为会后建议；不替用户决定或结束会议。

请骑士返回可供讨论的解释、依据与成立条件，或对同席观点的检验；充分说明理由，不强求结论或固定表格。只输出适合分享的分析，不要求内部思维链。

子 Agent 不自行派生其他 Agent，不读写画像、文件或执行会后任务，也不对外搜索、发送或操作。确有决定性事实待核实时交回主持人按主技能的任务切换及授权边界处理。主技能的追问门槛适用于全场，不能由每个子 Agent 各问一遍绕过。

## 统一出口与隐私

仅主持人向用户提出必要问题，通常聚焦一个；需要时以相应骑士的口吻自然呈现，不附加固定“接话扶手”。主持人负责区别用户认可、角色假设及会后建议，按主技能总结并等待解惑确认，不能把子 Agent 的“讨论完成”当作散会。

本地画像仅表示文件保存在本机；使用其摘要参与 Codex 推理仍会进入当前服务的模型上下文，并非离线处理。不额外传给独立 API 或实验服务；用户要求不用画像时不读取或转交。个人画像与会议纪要不进入通用仓库。
