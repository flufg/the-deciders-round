# 用户画像：采集、维护与圆桌应用

## 本地保存

真实画像放在实际加载的技能目录下 `state/user-profile.md`。Git只保存本规范和空框架；`state/` 必须被忽略。同步或更新技能时按文件复制通用资源，保留已有本地画像，不把个人画像回传到源码、仓库或提交记录。

用户可查看、更正、删除画像或停止维护。只采集对讨论有用的内容，不收集账号、证件、住址、精确财务数据、诊断、创伤细节或第三方隐私。文件写入不可用时明确说明未保存，不声称已经记住。

## 先整体，后补缺

画像采集是一项独立协作，不开决策会议、不按七席轮询。优先利用已有表达生成整体草稿，让用户补充纠正；已认领的描述不重新逐条询问。信息足够形成有用描述就推进，只有影响整体理解的矛盾才深入，不围绕小点连续追问。

用户给出MBTI时，可记录自我认同；如需候选描述，明确它们只供认领，不把整类人的刻板印象直接填入画像。未评论不等于认同；用户明确说“除指出的部分，其他基本符合”则可据此整理整体草稿，并保留已提出的例外。

落盘前呈现人物素描；用户对整体草稿的认可即足够，不要求逐条签字。后续用户明确的更正可直接更新并简短告知；新推断先留在当前讨论，得到认可再写入。新表达与旧描述冲突时允许改写，也允许不同情境下的特点并存。

普通会议优先推进议题，不为维护画像额外追问。需要确认的新认识留到自然停顿或总结时处理，也可暂不记录；用户主动纠正画像时即时响应。“今天状态不同”不自动改写长期描述，“这一直不符合我”才是明确更正。画像更新说明不得取代主持人对议题的总结和解惑确认。

## 可调整的素描框架

采用自然段或简短条目，不要求证据、时间戳、适用范围等逐条台账，也不要求填满所有栏目。

```markdown
# 我的圆桌画像（仅本地）

此画像可随时改写。当前表达优先于历史描述，未写出的内容不作推断。

## 自我认同与思考方式
MBTI（如用户认同）、理解问题的习惯、擅长的思考方式。

## 兴趣、行动与决策
投入的动力、收束选择的方式、现实权衡和行动节奏。

## 关系与情感
重视的相处方式、情绪表达、边界和难以接受的互动。

## 压力下可能出现的状态
用户认可的反复模式，以及不能被这些模式概括的例外。

## 适合我的圆桌方式
有效的分析和支持方式、希望被怎样挑战、推进与结束偏好。
```

核心价值或近期变化有材料时可自然融入或增设栏目，不凭空填充。保持同一份简洁素描，避免堆积近义标签和事件流水账。

## 借助优势，补充遗漏

以下例子说明如何将画像用于当前讨论，不是每场必做项目，同一特质可能兼有优势和代价：

- 分析能力能支撑推演时，提供清晰的结构和因果；当用户表达的感受或需要仍未处理时，将其与已有分析连接，帮助理解分析尚未解决的部分。
- 探索更多可能有价值时，帮助展开；当没有新增信息且等待成本上升时，说明继续探索的收益与代价。不能仅因用户还在比较就称其拖延。
- 用户愿意修正观点且当前判断确有漏洞时，可提出有依据的反方；检验已有充分结果后继续推进，不因用户能接受挑战就反复翻案。
- 边界长期被触碰时，分析停止、调整和退出的实际后果；不强求折中或维持关系。

## 从个人试用改进通用技能

当试用暴露采集或对话方法的问题时，只将可复用的方法写回通用规范。个人答案、MBTI类型、特质组合和关系案例留在本地；不把一个用户的特点变成所有用户的规则。
